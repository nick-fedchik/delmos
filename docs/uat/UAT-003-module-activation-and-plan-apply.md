# UAT-003: Активація модуля комплаєнсу та застосування плану

- **Статус:** Blocked — каталог модулів, `plan.apply` та workflow Review/Approval не реалізовані в `v1.0.0` (ціль `v1.x`, див. [ROADMAP.md](../architecture/ROADMAP.md)).
- **Перевіряє вимоги:** `SHR-02` (Module System Policy), `SHR-03` (Project Module Activation)
- **Роль виконавця:** Project Manager
- **Версія платформи:** потребує `v1.x`
- **Дата останнього виконання:** *Заблоковано відсутністю функціоналу.*

---

## Передумови

- Проєкт уже створено (див. [UAT-001](UAT-001-project-creation-and-generic-plan.md)), план перебуває в стані `draft`.
- Модуль `compliance.aspice` глобально дозволений адміністратором у Module Catalog (`ADM-010`) зі статусом `Available`.
- Виконавець автентифікований під роллю Project Manager із правом редагування плану проєкту.

## Кроки сценарію

1. Відкрити вкладку **Модулі та розширення** у проєктному плані (`PM-004`).
2. Переконатися, що в каталозі відображається лише модуль `compliance.aspice` зі статусом `Available` (заблоковані/призупинені модулі недоступні для активації).
3. Активувати модуль `compliance.aspice` (`PM-006`).
4. Переконатися, що в структурі плану з'явився VDA Scope (розділи `SYS.1`..`SYS.5`, `SWE.1`..`SWE.6`).
5. Заповнити обов'язкові поля, що з'явилися внаслідок активації модуля.
6. Подати план на затвердження командою `wp.submit` (`PM-013`).
7. Призначений Reviewer з `wp.review` фіксує позитивний висновок щодо точної ревізії плану.
8. Під іншим обліковим записом із явним правом `plan.approve` незалежно погодити цю ревізію; автор не може погодити власну ревізію.
9. Повернутися до Project Manager із окремим правом `plan.apply` та застосувати вже погоджену ревізію (`PM-014`).
10. Переконатися, що зміни набули чинності, а Review, Approval і застосування залишилися окремими записами аудиту.

## Очікувані результати

- Каталог модулів у проєкті показує лише глобально дозволені адміністратором модулі; спроба активувати заблокований модуль неможлива через інтерфейс.
- Після активації модуля структура плану розширюється новими розділами без втрати вже введених даних.
- Подання плану на затвердження переводить його у стан `in_review`; редагування в цьому стані обмежене відповідно до політики workflow.
- Самопогодження автора блокується на сервері, навіть за поєднання ролей.
- Застосування (`plan.apply`) успішне лише за наявності дійсного затвердження (`Approval`); спроба застосувати без затвердження відхиляється.

## Докази виконання (Evidence)

*Ще не виконано.* Після виконання сюди додається ідентифікатор ревізії плану до та після активації модуля, а також посилання на запис журналу аудиту про застосування плану.
