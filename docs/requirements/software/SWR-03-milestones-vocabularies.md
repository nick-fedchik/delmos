# SWR-03: Системні вимоги до віх, шлюзів та словників

Дата: 2026-09-23. Статус: нормативні вимоги підсистеми Milestones & Vocabularies.  
Ліцензія: Apache 2.0.  
Батьківські вимоги: [SHR-05](../stakeholder/SHR-05-milestones-gates-catalog.md), [SHR-10](../stakeholder/SHR-10-taxonomy-and-reference-data.md).  
Пов'язані архітектурні рішення: [ADR-001](../../architecture/decisions/ADR-001-all-in-postgresql-storage.md), [ADR-004](../../architecture/decisions/ADR-004-two-tier-module-governance-generic-plan.md).

---

#### SWR-09: Майлстоун як екземпляр каталогу типів віх
1. Віхи проєкту формуються на основі каталогу `Milestone Types` ядра (`project_kickoff`, `phase_gate`, `design_freeze`, `baseline_release`, `project_closure`) та модулів (`pdr`, `cdr`, `aspice_gate_review`, `safety_concept_freeze`).

#### SWR-10: Правила приймання віх (Milestone Acceptance Rules)
1. Кожен тип віхи містить декларативні правила приймання: перелік обов'язкових результатів, вимоги до статусу (`approved`) та наявність позитивного рішення комісії (`GateDecision: passed`).
2. Віха не може бути прийнята, якщо правила приймання повертають невиконані обов'язкові критерії.

#### SWR-11: Динамічні проєктні словники (Scoped Vocabularies)
1. Модуль при активації реєструє в проєкті словники класифікаторів (рівні ASIL, процеси ASPICE, статті витрат, валюти).
2. Словники доступні для вибору у випадаючих списках динамічних полів.

#### SWR-31: Версіовані довідники та таксономії
1. Модель розрізняє плоскі списки, дерева та поліієрархічні DAG. Перевірка ациклічності здійснюється через SQL CTE `CYCLE`.
2. Опубліковані релізи словників є незмінними. Перейменування назви терміна створює нову ревізію, зберігаючи стабільний `concept_id`.

#### SWR-32: Межі допоміжних функцій
1. Коментарі, обговорення, вкладення та сповіщення не замінюють формальних рішень щодо погодження ревізій артефактів.
