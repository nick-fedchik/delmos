# SHR-14: Базовий доступ, незалежне погодження та аудиторська видимість

- **Ідентифікатор:** `SHR-14`.
- **Стейкхолдери:** Engineer, Reviewer, Approver, Auditor, Viewer, Project Manager, System Administrator.
- **Формулювання:** DELMOS повинен надавати особі лише явно призначені дії в її просторі System, Programme чи Project; забезпечувати незалежне погодження точної ревізії Work Product та дозволяти аудитору перевірити рішення й докази без права змінювати їх. Читання, пошук, зв'язки й експорт не повинні розкривати об'єкти інших проєктів чи вміст поза дозволеною класифікацією.
- **Обґрунтування:** Без формального контракту базових ролей докладні use cases та архітектурний опис RBAC не захищають від міжпроєктного витоку даних, самопогодження або надмірних повноважень системного адміністратора.
- **Критерії приймання:**
  1. Роль без активного `RoleBinding` не дає доступу; заборони діють на прямий API, пошук, списки, граф і deeplink так само, як на UI.
  2. Автор не може самостійно погодити власну ревізію навіть при суміщенні ролей; Review, Approval і `plan.apply` є різними рішеннями.
  3. Viewer і Auditor можуть бачити лише дозволені записи; право експорту, керування доступом або зміни артефакту надається окремо.
  4. Історія ревізій і рішень має точні посилання, доступні для перевірки без відкриття секретів і даних чужого простору.
  5. Відкликання призначення впливає на наступний запит, включно з активною сесією та фоновою дією.
