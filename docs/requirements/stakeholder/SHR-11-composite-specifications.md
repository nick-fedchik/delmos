# SHR-11: Специфікації та композитні документи з пінуванням ревізій

- **Ідентифікатор:** `SHR-11`
- **Стейкхолдери:** Requirements Engineer, Verification Lead, Chief Engineer, Auditor.
- **Формулювання:** Користувач повинен мати змогу вести специфікацію вимог, тестів або інших характеристик як цілісний керований документ із самостійними елементами. Повторне використання елементів не повинно дублювати їх ідентичність, змішувати погодження або змінювати раніше зафіксований склад документа.
- **Обґрунтування (Rationale):** Необхідність читання специфікації як цілісного документа із розділами та контекстом без втрати гранулярності та атомарності вимог і тестів.
- **Критерії приймання:**
  1. Специфікація є складеним Work Product з деревом розділів та упорядкованими входженнями елементів.
  2. Кожна ревізія специфікації фіксує незмінний маніфест точних ревізій елементів (`CompositionManifest`).
  3. Погодження специфікації та погодження окремих вимог є повністю незалежними процесами.
  4. Проходження обов'язкового пакету сценаріїв приймання `SPEC-01..10`.
- **Декомпозиція на системні вимоги:** [SWR-33](../software/SWR-07-composite-specifications.md), [SWR-34](../software/SWR-07-composite-specifications.md), [SWR-35](../software/SWR-07-composite-specifications.md).
- **Пов'язані архітектурні рішення:** [ADR-003](../../architecture/decisions/ADR-003-composite-specification-manifests.md).
