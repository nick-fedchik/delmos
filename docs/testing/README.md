## 2. Команди перевірки

Наведені команди — **майбутній gate** після появи Go/Vue-коду, тестів та Makefile. Наразі прогнати їх у DELMOS неможливо; Draft UAT у [реєстрі](../uat/README.md) не є звітом про успішний тест.

```bash
go test ./...                 # unit + integration тести backend
cd web && npx vitest run       # unit тести frontend (Vue/TypeScript)
make validate                  # повний ворота якості: лінт, типізація, тести, збірка
```

## 3. Правило простежуваності

Кожен новий тест якісного рівня (Qualification) повинен мати явне посилання на ідентифікатор сценарію (`SPEC-NN`, `VEC-NN`, `GRP-NN`, `VIZ-NN`) у коментарі коду або назві тестової функції, щоб зберігати наскрізну простежуваність від стейкхолдерської вимоги до автоматизованого тесту.
