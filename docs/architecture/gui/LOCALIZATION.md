## 1. Межі локалізації

**Інтернаціоналізація (i18n)** означає, що компоненти, маршрути й ресурси від початку дозволяють змінювати мову, формат і напрямок письма без переробки бізнес-логіки. **Локалізація (l10n)** означає редакційно перевірений набір текстів і форматів для конкретної локалі. Мова документації репозиторію не визначає автоматично мову інтерфейсу користувача.

| Шар | Правило |
| --- | --- |
| Core GUI | Усі видимі тексти, доступні назви, підказки, помилки й системні сповіщення використовують стабільні ключі перекладу, а не конкатенацію речень у коді. |
| Модулі | Постачають тексти для своїх route keys, полів, станів, передумов та офлайн-довідки у версійованих ресурсах. Модуль не підмінює переклади Core. |
| Авторський інженерний контент | `WorkProduct` зберігає текст автора, код і точну ревізію; перемикання мови UI **не перекладає і не змінює** ці дані автоматично. |
| Зовнішній контент | Стандарт, назва інтеграції або імпортований матеріал має власне джерело, мову, права доступу та умови використання; переклад не створює нових прав. |

Рекомендований стартовий набір для планування перекладів: `uk-UA` та `en-US`, якщо командою затверджено переклади обох локалей. Перелік мов, базова локаль продукту і відповідальні за переклад мають бути затверджені до випуску; підтримку не можна декларувати лише за наявності частини рядків. Додаткова локаль проходить повний аудит UI, довідки, доступності та fallback. Коди мов/локалей використовують BCP 47; внутрішній `routeKey`, permission key, бізнес-код і URL ресурсу не перекладаються.

## 2. Текст, формат і вибір мови

- Мова UI визначається явним вибором користувача, потім налаштуванням інсталяції, потім узгодженим fallback; browser locale можна пропонувати при першому вході, але не змінювати нею вже обрану мову. Налаштування зберігається окремо від сесійних прав.
- Для множини, роду/відмінка й змінного порядку слів використовуються можливості підтримуваної i18n-бібліотеки та структуровані повідомлення, не вставляння окремих локалізованих слів у готове речення. Динамічні значення підставляються як дані з коректним екрануванням; HTML перекладача не виконується.
- Дати/час для аудитів, Gate Reviews, фінансів і строків показуються **абсолютно** з часовою зоною; відносні позначки допустимі лише як додаткова інформація разом із точною датою. Зберігання моменту події й локалізоване відображення — різні операції; тривалість, дата без часу й дедлайн у часовій зоні проєкту не ототожнюються.
- Числа, відсотки, розділювачі, одиниці, валюта та знак мінуса форматуються за локаллю для показу, але при розрахунках/обміні передаються структуровано, без парсингу відформатованого рядка. EVM-формули й округлення визначає доменний контракт, не мова браузера.
- Для майбутніх RTL-локалей компоненти використовують логічні напрямки/поля, перевіряються на перестановку панелей, графіків, клавіатурних команд і bidi-ізоляцію змішаних `code`/URL/ідентифікаторів; не заявляти підтримку RTL до тестування. Текст має витримувати збільшення довжини перекладу без обрізання критичних дій.

Орієнтир для точних дат: [Pajamas date and time](https://design.gitlab.com/content/date-and-time). Тексти інтерфейсу: [UI text](https://design.gitlab.com/content/ui-text) та [punctuation](https://design.gitlab.com/content/punctuation).

## 3. Незмінні ревізії та переклади контенту

Авторська мова артефакту має бути відома для редактора, пошуку й експорту. Якщо бізнесу потрібен переклад `WorkProduct`, його треба моделювати як **окрему керовану версію/похідний артефакт** із посиланням на конкретну вихідну ревізію, мовою, автором перекладу, окремими погодженням і хешем. Спосіб зберігання та семантика зв'язку потребують окремого ADR і SWR перед реалізацією; цей документ не змінює модель БД сам по собі. Переклад не успадковує статус `approved` або сертифікаційну доказовість джерела автоматично. При зміні джерела переклад позначається таким, що потребує перегляду, з явним шляхом до обох версій.

Пошук може враховувати мову й морфологію тільки із збереженням `classification` та прав на кожний результат. Не відправляти `restricted` контент зовнішнім перекладацьким сервісам без окремої політики, дозволу та аудиту. Вміст нормативних стандартів і зовнішніх документів перекладати або цитувати лише з дотриманням ліцензійних прав; локалізована назва не означає локалізований офіційний текст стандарту.

## 4. Контент-дизайн Guided UI

Для кожного маршруту модуля редактор текстів готує обидві локалізації п'яти відповідей із [GUIDED_EXPERIENCE.md](GUIDED_EXPERIENCE.md): де, навіщо, передумови, дія, наступний крок. Назва дії є дієсловом і конкретним результатом; помилка пояснює причину та спосіб вирішення без витоку прихованих даних. Help-текст не повторює label. Заголовок порожнього стану, aria-label, тексти screen reader, повідомлення про недоступний модуль, email/експорти та підказки клавіатури проходять той самий процес рецензування, що й видимі кнопки.

Терміни `Work Item`, `Work Product`, `revision`, `baseline`, `approval`, `plan.apply` узгоджуються з [глосарієм](../GLOSSARY.md); локалізований ярлик не змінює ідентифікатор доменної команди. Для багатомовних повідомлень підтримуються шаблони з названими плейсхолдерами та коментарем для перекладача про контекст, коли одна фраза може мати кілька значень.

## 5. Процес і критерії приймання

1. Новий ключ або текст додається разом із контекстом використання, власником та скриншотом/прикладом стану; модуль версіонує ресурси поряд із UI-внеском.
2. Відсутній переклад дає визначений fallback і сигнал команді, а не порожню кнопку чи змішані півречення. Для критичних дій і SoD-пояснень неповний пакет перекладів блокує ввімкнення локалі.
3. Перекладач і рецензент галузевої термінології перевіряють зміну; автоматичний переклад може бути чернеткою, але не остаточним нормативним текстом.
4. Автоматизовано перевіряються відсутні ключі, плейсхолдери та некоректний формат ресурсів. Ручні сценарії проходять обрані локалі на desktop/mobile, zoom, світлій/темній темі, клавіатурі й screen reader.
5. Контрактний тест доводить: зміна мови UI не змінює `payload_hash` затвердженої ревізії; точний дедлайн лишається тим самим моментом незалежно від формату відображення; експорт указує мову інтерфейсу окремо від мови оригіналу артефакту.
