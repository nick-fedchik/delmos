## 2. Мінімальний пакет для першого Guided UI сценарію

Для маршруту створення проєкту дизайнер формує: перевірену мету новачка; карту кроків і переходів між ролями; схему навігації; wireflow з порожнім/помилковим/успішним станом; тексти `uk-UA`/`en-US`; макет у desktop/mobile та світлій/темній темі; поведінку фокусу/клавіатури; сценарій тесту з новим користувачем; посилання на [UAT-001](../../uat/UAT-001-project-creation-and-generic-plan.md). Збереження чернетки, помилки мережі й повернення за deeplink перевіряються до закриття роботи над екраном.

Після цього той самий пакет застосовується до плану, `WorkProduct`, трасованості й активованих модулів. Власник модуля додає свої правила й пояснення, але не створює нову глобальну навігацію чи альтернативний набір станів.

## 3. Критерій готовності handoff

Завдання на реалізацію екрана містить: цільову роль і Job-to-be-Done; `routeKey`/адресу; пряме посилання на відповідну вимогу або use case; права, активацію модуля і SoD; стани `loading/empty/error/forbidden/success` і повернення після 409; мобільні зміни; тексти й джерела локалізації; keyboard/ARIA; критерії UAT й обмеження на дані для аналітики. За відсутності одного з цих пунктів власник фіксує конкретний відкритий ризик, а не позначає дизайн як завершений.

## 4. Як перевіряти придатність

Дати людині, яка не читала документацію платформи, три завдання: створити проєкт із планом, пояснити різницю між збереженням і затвердженням артефакту, знайти причину заблокованого Gate Review. Заміряти завершення, час, помилки, потребу в підказці модератора та розуміння наслідку; повторити для вузького екрана, клавіатури й доступної локалі. Порівняти результати з попередньо заявленими цілями, оновити wireflow і текст, а не підміняти факт позитивним враженням команди.
