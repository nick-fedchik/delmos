# ADR-006: Інтеграція проєктної економіки (Project Economics) та обліку ресурсів

- **Статус:** Прийнято (Accepted)
- **Дата:** 2026-09-23
- **Контекст:** Традиційні ALM/ELM системи (Polarion, DOORS) повністю ігнорують економічний контекст інженерії: вони оперують вимогами та тестами, але не знають про бюджети, ліміти фінансування, вартість праці чи аналіз освоєного обсягу. З іншого боку, класичні ERP-системи (SAP) відірвані від інженерних артефактів і ревізій. В інженерному життєвому циклі критично важливо оцінювати вартість змін (Change Request Cost), планувати місткість команд проти розкладу та контролювати освоєний обсяг на фазових шлюзах.
- **Рішення:** Розширити можливості платформи DELMOS модулями проєктної економіки та ресурсів за міжнародними стандартами (PMBOK, SWEBOK, ISO 21502, ASPICE MAN.3):
  1. *Ядро:* підтримка базової сутності `WorkRecord` для табельного обліку фактично відпрацьованого інженерами часу над артефактами чи завданнями.
  2. *Модуль `management.resources`:* облік виробничих календарів (`WorkingCalendar`), планування зайнятості та місткості у FTE (`ResourceAllocation`), контроль перевантаження ресурсів та SoD-правила незалежності ролей.
  3. *Модуль `management.economics`:* затвердження базового кошторису (`CostBaseline`), розрахунок прямих трудовитрат за внутрішніми ставками ролей (`LaborRate`), фіксація матеріальних та NRE витрат (`ExpenseRecord`, CapEx проти OpEx за IAS 38).
  4. *Контроль ефективності:* розрахунок стандартних метрик Earned Value Management: $PV$ (Planned Value), $AC$ (Actual Cost), $EV$ (Earned Value), індексів $CPI = EV/AC$, $SPI = EV/PV$, прогнозу завершення $EAC = BAC/CPI$ та валового прибутку (P&L для комерційних робіт).
  5. *Шлюзовий контроль (Funding Limit Gate):* фазовий шлюз блокується, якщо витрати перевищують ліміт фінансування етапу без схваленого запиту на зміну бюджету (CR).
- **Наслідки:**
  - *Позитивні:* Єдиний простір інженерії та фінансів; точна оцінка вартості запитів на зміни; готовність до аудитів комерційної та інвестиційної ефективності R&D.
  - *Негативні / Компроміси:* Необхідність ведення ставок і регулярного списання годин; підвищені вимоги до захисту фінансової інформації (обмеження доступу до ставок за ролями).
