# ADR-001: Використання PostgreSQL як єдиного сховища реляційних, графових і векторних даних

- **Статус:** Прийнято (Accepted)
- **Дата:** 2026-09-23
- **Контекст:** В інженерних системах ELM/ALM критично важливими є обхід графів простежуваності (RTM), семантичний аналіз тексту вимог і тестів, а також транзакційне збереження реляційних сутностей і ревізій. Традиційний підхід полягає у розгортанні спеціалізованих баз (Neo4j для графів, Milvus/Qdrant/Pinecone для векторів, PostgreSQL для метаданих). Це призводить до розподілених транзакцій без ACID, складності синхронізації прав доступу та високих витрат на експлуатацію.
- **Рішення:** Затвердити PostgreSQL як єдину СУБД для всіх типів інженерних даних у DELMOS:
  1. Реляційні сутності та аудит: стандартні таблиці з підтримкою транзакційного механізму ACID.
  2. Векторні ембедінги: використання нативного розширення `pgvector` (типи `vector`, HNSW-індекси, косинусна відстань `<=>`).
  3. Графовий аналіз простежуваності: використання стандартних рекурсивних запитів `WITH RECURSIVE` із нативним контролем зациклень `CYCLE target_id SET is_cycle USING path`.
  4. Матеріалізовані ієрархічні шляхи: використання вбудованого розширення `ltree` для швидкого індексування дерев розділів специфікацій та WBS.
- **Наслідки:**
  - *Позитивні:* Повна транзакційна цілісність; єдина авторизаційна модель (фільтрація прав і векторна відстань в одному SQL-запиті); резервне копіювання однією утилітою `pg_dump`; автономне розгортання на сервері Ubuntu без сторонніх контейнерів.
  - *Негативні / Компроміси:* Підвищені вимоги до оперативної пам'яті (RAM) сервера БД для утримання HNSW індексів; необхідність налаштування `shared_buffers` та `maintenance_work_mem`.
- **Пов'язані вимоги:** SHR-12, SWR-36, SWR-37; специфікація [VECTOR_AND_GRAPH_DATA.md](../VECTOR_AND_GRAPH_DATA.md).
