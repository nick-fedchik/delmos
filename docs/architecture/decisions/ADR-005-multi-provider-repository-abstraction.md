# ADR-005: Мультипровайдерна абстракція сховищ та трекерів (RepositoryProvider)

- **Статус:** Прийнято (Accepted)
- **Дата:** 2026-09-23
- **Контекст:** Попередні розробки мали надмірну жорстку прив'язку до єдиного зовнішнього хостингу коду (GitLab). Однак замовники та різні департаменти використовують широку палітру інфраструктурних рішень (GitHub у відкритих проєктах, Azure DevOps у корпоративному сегменті Tier-1, Bitbucket у середовищах Atlassian, локальні легкі сервери Forgejo/Gitea у закритих контурах або внутрішні БД без зовнішнього Git). Жорстка прив'язка до одного вендора обмежує застосування системи.
- **Рішення:** Запровадити інтерфейсну абстракцію `RepositoryProvider` для сховищ Docs-as-Code та коду:
  1. *Внутрішнє сховище (Internal Storage):* збереження документів безпосередньо у базі PostgreSQL DELMOS або в локальному bare Git-репозиторії на сервері. Проєкт створюється в один клік без зовнішніх налаштувань.
  2. *Чистий віддалений Git (Plain Remote Git):* робота зі стандартними репозиторіями за протоколами SSH або HTTPS.
  3. *Корпоративні адаптери (Enterprise Adapters):* спеціалізовані підключення до GitLab, GitHub, Azure Repos, Bitbucket, Gitea через їхні офіційні REST API.
  4. Інтеграція здійснюється без примусового локального клонування всього репозиторію на диск сервера (читання/запис окремих блобів і комітів через API).
  5. Тимчасова недоступність зовнішнього Git не блокує локальну роботу, авторизацію чи читання проіндексованих артефактів (Graceful Degradation).
- **Наслідки:**
  - *Позитивні:* Повна вендорна незалежність; швидкий старт нових проєктів без потреби одразу створювати зовнішній репо; підтримка закритих контурів безпеки.
  - *Негативні / Компроміси:* Необхідність реалізації та тестування окремих адаптерів під кожен REST API; різниця у можливостях вендорів (наприклад, підтримка вебхуків чи детальних статусів CI/CD).
- **Пов'язані вимоги:** SHR-01, SWR-02; специфікація [PROJECT_MODEL.md](../PROJECT_MODEL.md).
